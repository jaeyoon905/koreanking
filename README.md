# 라벨코스트 (LabelCoast)

종이 일지·서류를 사진/PDF로 넣으면 AI가 칸을 읽고(결재는 사람), 로트 추적·만료 알림·수출입 서류 체크가 되는 A사용 도구.

## 실행

| 모드 | 방법 | 상태 저장 | 추출 |
|---|---|---|---|
| 서버 | `run.bat` → http://localhost:8765 | `server/labelcoast.db` | 업로드 → AI(키 있을 때) / 미리 읽어 둔 값 |
| 오프라인 | `index.html` 더블클릭 | 브라우저 localStorage | 미리 읽어 둔 값 |

서버 모드 추가 주소: 바이어 공개 LOT `/api/lot/<lot>/public`, 식약처 프록시 `/api/mfds/I2500?BSSH_NM=...`

## 파일

| 파일 | 역할 |
|---|---|
| index.html | 진입점 |
| style.css | 디자인 |
| data.js | 품목·규칙 파일(HK/TW/TH/JP)·시드 |
| apply.js | 서류 종류별 반영 규칙 |
| fixtures.js | 받은 서류 9종 추출 결과. 키 없을 때 사용 |
| import.js | ⑧ 수입 체크 |
| app.js | 화면 8개 |
| agent/graph.py | LangGraph 팀: 접수·읽기·검증·작성·개발·결재 |
| agent/judge.js | 규칙 엔진 래퍼 (Python → data.js) |
| server/app.py | HTTP + SQLite |
| server/fixture_dump.js | 서버가 fixtures.js 를 읽을 때 사용 |

## 화면

1. ① 라벨 판정 — 라벨 값과 도착국 → 항목별 통과/수정/확인, 영양값 출처 표
2. ② 품목 입력 — 한 번 입력 → 나라별 영양 환산·알레르겐·첨가물 문구
3. ③ 품목 규격서 — ②의 값으로 규격서 → 인쇄(PDF)
4. ④ 선적 입력 — 선적 한 줄 → LOT·원장, 선적 목록
5. ⑤ LOT 조회 — 바이어 면(서류 수준) / 회사 면(원어 로트·출고처·클레임 종류별 기록)
6. ⑥ 대시보드 — 등록·인증 만료 D-day, 고시 개정
7. ⑦ 서류 넣기 — 접수부 → 읽기부 → 검증부 → 결재(승인/반려)
8. ⑧ 수입 체크 — 수입 선적 1건의 서류 체크리스트

발표 순서: ⑦에서 시연 초기화(빈 원장) → 7-3 → 7-1 → 7-2 → 5-2(체크 후 승인) → 6 → 8 → 1 → 4 → 제품사진 → ⑤ 20260410-LB 회사 면 → ⑥ → ⑧

## 원칙

- 판정은 data.js 규칙 파일, 계산은 코드, AI는 읽기·짝짓기·초안만.
- 원장 반영은 사람 승인 뒤에만.
- 계좌·단가 있는 서류는 가린 뒤에만 처리(가리기 전엔 AI에 보내지 않음).
- 마스킹: 회사 A사, 바이어 U사·T사·S사, 선박 삼○호. 실명·계좌·단가는 코드와 화면 어디에도 없어야 한다.

## 키 넣기

`.env.example`(상위 폴더)을 `.env`로 복사하고 `ANTHROPIC_API_KEY`를 채우면 ⑦ 업로드가 AI 추출로 바뀐다. 코드 수정 없음. `.env`는 공유·커밋 금지.

## 점검

```
python -X utf8 agent/graph.py                                   # 규칙 회귀 4건
node -e "new Function(require('fs').readFileSync('app.js','utf8'))"   # app.js 문법
```

| 주기 | 데이터 |
|---|---|
| 회사당 1회 | 영업등록번호(식약처 API), HACCP·상대국 등록 번호와 만료일, 공장 주소·담당자 |

| 계속 | 입고 기록(지금 쓰는 장부 그대로), 선적마다 한 줄 |


## 10/31 저녁 추가분

- **수입 서류도 ⑦에 넣는다**: 수입 인보이스(계좌·금액 가린 뒤), B/L, 일본 정부 수입용 식품 신고서(Declaration), DHL 운송장. 승인하면 ⑧ 수입 체크리스트가 시드가 아니라 실제 상태로 채워진다(신고서 n/m장, B/L 원본 도착 메모).
- **품목 여러 개**: ②③④ 상단에서 LB / SR(T사 신규 250g) 선택. 영양 성적서 없는 품목은 "성적서 필요"로 표시.
- **바이어 양식 규격서**: ⑦에서 U사 商品規格書를 승인하면 ③에 "양식: U사" 선택이 생기고 그 칸 순서대로 출력된다. 비어 있는 칸은 노란색.
- **중국 규칙 파일**: GB 7718-2025(2027-03-16 시행) 11항목, 각 항목에 원문 조항 번호(`src`). 영양 환산표는 GB 28050 원문 확인 뒤 추가 예정이라 비어 있음.
- **서버 운영**: `.env`에 `LC_PASSWORD=...` 를 넣으면 로그인(1계정)이 켜진다. 없으면 무인증 개발 모드. `GET /api/backup` 으로 상태 JSON 내려받기, 서버 시작 시 `server/backup/`에 하루 1개 DB 사본. 포트는 `LC_PORT`.
- **AI 추출 켜기**: `.env`에 `ANTHROPIC_API_KEY` 를 넣고 서버 재시작 → ⑦ 업로드가 내용 기반 분류 + 양식별 힌트(입고검사서·가공일지·포장일지·패킹리스트·수입신고서)로 추출된다. 켠 뒤 첫 할 일은 `python -X utf8 agent/eval_extract.py` 로 받은 원본 9개를 AI로 읽혀 사람 값과 칸별 대조하는 것(결과 `agent/eval_report.json`).
- **점검 한 번에**: `python -X utf8 tests/smoke.py` (정적 검사·금지어·오프라인·서버 모드 40항목, 결과 `tests/last_run.txt`).
